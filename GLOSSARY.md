# Словарь терминов проекта

Только термины, прямо или косвенно связанные с разработкой для ИИ. Пополняется по ходу работы. Формат: термин [предметная область] — определение.

## RAG и поиск

- RAG [ИИ-архитектура] — Retrieval-Augmented Generation: модель отвечает на вопрос не из своей памяти, а по найденным фрагментам ваших документов. Отсюда точные ответы со ссылками на источники.
- Corrective RAG [ИИ-архитектура] — усложнение RAG: перед генерацией LLM проверяет релевантность найденных фрагментов и при необходимости расширяет запрос и ищет заново (у нас — до 2 раз).
- LLM [ИИ] — большая языковая модель, «мозг», генерирующий текст. В проекте — локальная Qwen2.5-3B через Ollama, без платных API.
- Эмбеддинг [ИИ] — превращение текста в вектор чисел так, что похожие по смыслу тексты дают близкие векторы. Основа поиска по смыслу.
- Вектор [ИИ-поиск] — упорядоченный набор чисел, представляющий текст математически; сравнивая векторы, машина сравнивает смыслы.
- Косинусная близость [ИИ-поиск] — мера похожести векторов через угол между ними; альтернатива L2 (расстояние между концами). Для нормализованных векторов порядок одинаковый.
- Токен [ИИ] — минимальная единица текста для модели (часть слова, слово, знак); также единица измерения контекста.
- Контекст (окно контекста) [ИИ] — объём текста, который модель держит «в голове» за один вызов; поэтому в ответ подаём только топ-6 чанков.
- Промпт [ИИ] — текст-обращение к модели: инструкция + данные. Качество промпта сильно влияет на качество ответа.
- Чанк [RAG] — кусок документа ~1200 символов, единица индексации и поиска; помнит источник и позицию в файле.
- Чанкинг [RAG] — разбивка документов на чанки: код — по границам функций, текст — по абзацам.
- Перекрытие, overlap [RAG] — дублирование 200 символов между соседними чанками, чтобы мысль на границе разреза не потерялась.
- Сплиттер [RAG] — инструмент разрезки текста; наш — RecursiveCharacterTextSplitter из LangChain (абзацы → предложения → слова).
- Метаданные чанка [RAG] — данные о происхождении чанка: файл-источник, номер куска, тип документа. Дают источники в ответах.
- Источники, sources [RAG] — список файлов, из которых собран ответ; требование задания к ask_question.
- Индексация [RAG] — обработка папки в базу: скан → чтение → чанки → эмбеддинги → ChromaDB. Выполняется инструментом index_folder.
- Retriever [RAG] — модуль, находящий релевантные чанки по запросу; наш — гибридный (BM25 + вектор → RRF).
- Retry-цикл [RAG] — повтор поиска с расширенным запросом, если первый не нашёл релевантного; максимум 2 повтора.
- Грейдинг чанков [RAG] — шаг Corrective RAG: LLM оценивает каждый найденный чанк «релевантен/нет» до генерации ответа.
- BM25 [ИИ-поиск] — алгоритм поиска по словам: документ релевантнее, если слова запроса чаще в нём встречаются, редкие слова весят больше. «Словесная нога» гибридного поиска.
- IDF [ИИ-поиск] — обратная документная частота в BM25: чем реже слово в корпусе, тем оно информативнее.
- Корпус [ИИ-поиск] — набор документов, по которому идёт поиск (вся проиндексированная база).
- Токенизация [ИИ-поиск] — разбиение текста на слова-токены для BM25; у нас с поддержкой кириллицы.
- Гибридный поиск [ИИ-поиск] — одновременный поиск по словам (BM25) и по смыслу (векторы) со слиянием результатов через RRF.
- RRF [ИИ-поиск] — Reciprocal Rank Fusion: документу начисляется 1/(k + позиция) в каждом списке, суммы складываются; найденный обоими методами ранжируется выше.
- Sparse / dense retrieval [ИИ-поиск] — два семейства поиска: sparse — по словам (BM25), dense — по «плотным» векторам смысла.

## Библиотеки и модели

- LangChain [ИИ-библиотека] — набор инструментов для документов и LLM: лоадеры, сплиттеры, клиенты моделей. В проекте — детали.
- TextLoader [LangChain] — загрузчик текстовых файлов из LangChain; читает файл в «документ» с полем page_content.
- LangGraph [ИИ-библиотека] — оркестратор LLM-цепочек как графа шагов с условными переходами; на ней построен наш Corrective RAG.
- FastMCP [ИИ-библиотека] — Python-фреймворк для MCP-серверов: инструмент объявляется функцией с description.
- ChromaDB [ИИ-БД] — встраиваемая векторная база: хранит чанки и векторы, ищет ближайшие по смыслу; in-process, персистентна на диске.
- Ollama [ИИ-инструмент] — программа для запуска локальных LLM как сервиса; по HTTP отдаёт ответы модели и эмбеддинги.
- Qwen2.5-3B [модель] — наша локальная LLM (3 млрд параметров): грейдинг, перезапрос, генерация ответов.
- nomic-embed-text [модель] — модель эмбеддингов в Ollama; альтернатива дефолтной ChromaDB, переключается конфигом (опциональное задание).

## Протоколы

- MCP [ИИ-протокол] — Model Context Protocol: стандарт подключения внешних инструментов к ИИ-агенту в IDE (Copilot, Claude). Наш сервер отдаёт 4 инструмента.
- Хост-агент [ИИ-протокол] — ИИ-ассистент в IDE, который сам решает, когда вызвать MCP-инструмент, ориентируясь на его description.
- Streamable HTTP [ИИ-протокол] — режим MCP-сервера как веб-сервиса (http://localhost:8000/mcp); выбран вместо stdio ради Docker.

## ИИ-процесс разработки

- opencode [ИИ-инструмент] — агентная CLI-среда разработки, в которой ведётся весь проект (эта сессия).
- GLM 5.3 [модель] — модель, исполняющая задачи агента в opencode.
- superpowers, скилл [ИИ-процесс] — плагин с процессами-инструкциями для агента (планирование, TDD, ревью); скилл — один такой процесс.
- Context7 [ИИ-инструмент] — MCP-сервер с актуальной документацией библиотек, подключён к агенту для точных ответов по API.
- Субагент [ИИ-процесс] — отдельный агент со своим контекстом, выполняющий одну задачу и возвращающий отчёт; главная сессия координирует и ревьюит.
- DONE_WITH_CONCERNS [ИИ-процесс] — статус отчёта субагента «сделано, но есть сомнения»; сигнал контроллеру разобраться перед приёмкой.
- FakeLLM / FakeEmbedder [тестирование ИИ] — детерминированные подмены модели и эмбеддера в тестах: без сети, ответы по списку; позволяют тестировать RAG-конвейер офлайн.
